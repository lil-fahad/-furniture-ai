# Furniture AI — حزمة ويندوز 1.1

المشروع يتضمن واجهة تصميم، قاعدة بيانات محلية، حسابات خاصة، طابور معالجة، خدمات النماذج، وخطوط التدريب والتقييم. الموردون مؤجلون.

## أسرع تشغيل

1. ضع **FurnitureAI-Windows-v2.zip** و**INSTALL-FURNITURE.cmd** في مجلد واحد، مثل Downloads.
2. افتح **INSTALL-FURNITURE.cmd**. يفحص بصمة ZIP، ويفك الحزمة في مجلد مستقل داخل حساب ويندوز، ثم يفتح نافذة التحكم.
3. إذا لم تكن Python 3.12 64-bit متاحة، يحاول ملف التشغيل تثبيتها لحساب المستخدم عبر Windows Package Manager. إذا كانت الأداة غير متاحة، يعرض رابط Python الرسمي. لا يغيّر سياسات PowerShell أو تعريف GPU.
4. اضغط **Check GPU / فحص الجهاز**، ثم **Setup / تجهيز البيئة**.

الطريقة اليدوية: اختر Extract All على ZIP، ثم افتح **START-WINDOWS.cmd** من المجلد الناتج. ملف التشغيل موجود في جذر الحزمة؛ لا توجد طبقة مجلد إضافية داخل ZIP. لا تنقل ملف التشغيل وحده بعيدًا عن بقية الملفات.

التشغيل من PowerShell يبقى متاحًا. انتقل إلى المجلد الذي يحتوي ملف التشغيل فعليًا ثم استخدم:

~~~powershell
.\START-WINDOWS.cmd --check-package
.\START-WINDOWS.cmd --doctor-only
.\START-WINDOWS.cmd --setup-only
~~~

## تشغيل مشروع التصميم كاملًا محليًا

بعد تجهيز البيئة، افتح تبويب **Design studio / المشروع**:

1. اضغط **Download models** لتنزيل الأوزان الرسمية المثبتة في models.lock.json والتحقق من بصماتها. التحميل كبير؛ الحزمة البرمجية لا تتضمن الأوزان.
2. اختر اسم مستخدم وكلمة مرور من 12–256 حرفًا. عند التشغيل اللاحق استخدم بيانات الدخول نفسها.
3. اضغط **Open studio**. يفتح المتصفح على http://localhost:8765.
4. سجّل الدخول، وارفع صورة غرفة أو مخططًا، ثم اطلب التحليل والتصميم بعد تأكيد القياسات.

ينشئ المسار قاعدة SQLite محلية مع ترحيلات Alembic، ويشغّل API وعامل معالجة واحدًا وخادم نماذج واحدًا. يستمع إلى 127.0.0.1 فقط. يحتفظ بعائلة نماذج واحدة في الذاكرة، ويبدّل بين التحليل والتوليد والتقييم حسب المرحلة. Qwen يعمل عبر Transformers محليًا، فلا يحتاج هذا المسار إلى vLLM أو Docker.

وجود GPU لا يضمن ملاءمته: المسار الآلي يتطلب NVIDIA/CUDA، وQwen 7B وSDXL يحتاجان ذاكرة كافية. تنزيل الملفات لا يثبت قدرتها على الاستدلال على جهازك. Setup يجري اختبار CUDA فعليًا؛ قياس زمن وجودة التصميم الكامل على GPU يُجرى على جهاز التشغيل.

الحسابات وبيانات المشاريع داخل data/desktop. تحفظ كلمة المرور كتجزئة في قاعدة البيانات، ولا تُكتب في سجل العمليات أو سطر الأوامر. لا تُرفع الصور أو بيانات الدخول تلقائيًا لخدمة خارجية. أبقِ نافذة التحكم مفتوحة؛ زر Stop يوقف العمليات التابعة للمشروع.

هذا مسار محلي لمستخدم واحد وعامل واحد. للنشر متعدد العملاء والعمّال استخدم PostgreSQL وخدمات النماذج المستقلة وHTTPS وفق docs/DEPLOYMENT.md.

## تدريب بيانات COCO التي أرسلتها

افتح تبويب **Training / التدريب**:

1. اختر **Grounding DINO** للكشف أو **SAM 2.1** للأقنعة.
2. اضغط Browse واختر **annotations_trainval2017.zip** دون فك ضغطه.
3. اضغط **Check data** للتحقق من اختيار الأرشيف، ثم **Train**.

يبحث البرنامج تلقائيًا في مجلد التنزيلات الحقيقي لويندوز، ومجلد المشروع ومجلدي الاستخراج الخارجيين، ومجلد data/input. يمكنك اختيار أي مسار يدويًا. يتحقق من بنية ZIP قبل تثبيت الحزم أو تنزيل الصور.

~~~powershell
.\START-WINDOWS.cmd --task dino --annotations "D:\Datasets\annotations_trainval2017.zip"
.\START-WINDOWS.cmd --task sam2 --annotations "D:\Datasets\annotations_trainval2017.zip"
~~~

الأرشيف المرفق يحتوي تعليقات JSON وليس صور RGB. قسم instances يفهرس 118,287 صورة تدريب و5,000 صورة تحقق. الصور المطلوبة تُنزّل من مصدر COCO الرسمي وتُفحص أبعادها وبصماتها.

الفئات المختارة: كراسي وكنب وأسرّة وطاولات طعام. الإعداد الافتراضي ينتقي الصور المدرجة بترخيص CC BY 2.0. خيار Research يُمرّر فعليًا إلى المستورد ويستخدم مجلد coco-research مستقلًا، لأن تغيير تراخيص الاختيار داخل المجلد نفسه غير مسموح.

يعيد المستورد استخدام الصور الصحيحة المكتملة. لا يبدأ التدريب إذا كانت بطاقة البيانات ready_for_training=false. مجموعة val2017 محفوظة للاختبار النهائي، والتحقق التدريبي مأخوذ من train2017.

## النماذج والبيانات الأخرى

| الوظيفة | التنفيذ |
|---|---|
| كشف الأثاث | Grounding DINO Base |
| فصل القطع | SAM 2.1 Hiera Small |
| العمق النسبي | Depth Anything V2 Small |
| المخططات | Qwen المحلي افتراضيًا؛ FloorplanNet يحتاج أوزانًا مدرّبة؛ CubiCasa مسار بحثي |
| توزيع القطع | محلّل هندسي بقيود افتراضيًا؛ Layout Transformer متاح للتدريب والترقية |
| توليد التصميم | SDXL + ControlNet Canny/Depth + Inpainting |
| التشابه | SigLIP 2 Base |
| تحليل الصورة وتقييم المقترحات | Qwen2.5-VL-7B-Instruct |
| ترتيب المقترحات | ترتيب موزون افتراضيًا؛ PairwiseRanker يحتاج تدريب تفضيلات |

لا يُعرض Layout Transformer أو Ranker غير المدرّب على أنه نموذج متعلّم جاهز. يرفض النظام تداخل الأثاث أو خروجه عن الغرفة هندسيًا؛ الصورة المولّدة تظل تصورًا بصريًا وليست إثبات قياس.

~~~powershell
.\START-WINDOWS.cmd --task siglip --abo-archive "D:\Datasets\FurnitureAI-ABO-furniture.zip"
.\START-WINDOWS.cmd --task layout --research --spatiallm-archive "D:\Datasets\FurnitureAI-SpatialLM-layouts-research.zip"
~~~

SigLIP يحتاج أرشيف ABO الكامل المحتوي على الصور؛ أرشيف قوائم التدريب وحده لا يكفي. SpatialLM ونتائج التدريب عليه غير تجارية. أما تدريب العمق وSDXL وQwen والمخططات والتفضيلات فتوجد أوامره وعقود بياناته في docs/TRAINING.md.

## الأخطاء والاستئناف

زر Logs يفتح السجلات. أحدث حالة في logs/latest-session.json، وتقرير GPU في data/gpu-report.json. إذا لم تُثبّت PyTorch بعد، يكتمل جمع التقرير لكن تظهر الحالة needs_setup، وليس نجاح CUDA.

يمنع المشغّل عمليتين متزامنتين من تغيير بيئة التدريب نفسها. تنتهي قفلة التشغيل تلقائيًا عند خروج العملية؛ وجود ملف operation.lock وحده لا يعني أن التطبيق ما زال مشغولًا.

من زر Resume اختر مجلد epoch الذي يحتوي training-state.json. يُستعاد عدد الدورات وإعداد التدريب الأصلي، ويستخدم مجلد التشغيل الأصلي تلقائيًا:

~~~powershell
.\START-WINDOWS.cmd --task dino --resume "D:\Furniture\checkpoints\dino-RUN\epoch-0002" --annotations "D:\Datasets\annotations_trainval2017.zip"
~~~

بعد توقف تحميل، أعد العملية نفسها. لا تحذف بياناتك أو تغيّر البيئة يدويًا. عند تعارض منفذ الشبكة يتوقف التشغيل برسالة واضحة، ولا يقتل برامج أخرى.

## بناء الحزمة من المصدر

~~~powershell
py -3.12 scripts/build_windows_package.py --output dist/FurnitureAI-Windows-v2.zip
~~~

ينتج ZIP مسطحًا وملف INSTALL-FURNITURE.cmd مطابقًا لبصمته. تُستبعد البيئات والبيانات والسجلات والإعدادات الخاصة. package-manifest.json يفحص سلامة الملفات بعد الاستخراج؛ لا يمثّل توقيع ناشر مستقلًا.

## التحقق وحدوده

تشمل الاختبارات: اكتشاف مجلدات الاستخراج المتداخلة، مسارات بها مسافات، بنية COCO، فصل البيانات البحثية، تجزئات الحزمة، منع التشغيل المتزامن، حفظ الأخطاء، تهيئة الحسابات والمهاجرات، مسارات الخدمة الموحدة، ورفض ردود Qwen غير المطابقة.

اختبار Windows CI يشغّل ملف CMD ونافذة التحكم واختيار ZIP. اختبارات النماذج الصغيرة تؤكد سلامة واجهات الحساب والتدرجات، ولا تُستخدم كدليل جودة للأوزان الكبيرة. التشغيل الفعلي للأوزان على GPU وتقييم الجودة لا يُستبدلان باختبارات CPU.

المراجع: [Python على Windows](https://docs.python.org/3.12/using/windows.html)، [Windows Package Manager](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)، [Qwen عبر Transformers](https://huggingface.co/docs/transformers/v4.57.1/en/model_doc/qwen2_5_vl)، [COCO](https://cocodataset.org/#download).
